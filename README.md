## 实时硬链接+（LinkMonitorPlus）

基于 MoviePilot 内置插件 **LinkMonitor 1.7.1**（作者 [jxxghp](https://github.com/jxxghp)）修改。

### 为什么需要它

原版判断"处理过没有"只有一个依据：**目标路径有没有文件**。于是：

```
1原文件/xxx.mkv  →硬链→ 2硬链/xxx.mkv →(改名/整理搬走)→ 媒体库/xxx.mkv
```
链接被搬走后目标就空了 → 下次同步**又链一次**，产生多余硬链、触发多余整理。

### 改成了什么

| 能力 | 说明 |
|---|---|
| 已处理记录 | `源文件路径 → {size, mtime, ino, target}`，落在 `/config/plugins/LinkMonitorPlus/linked.json` |
| 跳过判据 | 记录命中且文件未变 → 跳过（**目标被搬走也算处理过**） |
| 自动补登记 | 链接成功时登记；**目标已存在时也登记** → 升级后跑一次全量同步即可纳入存量 |
| 兜底判据 | 无记录时用 `st_nlink > 1` 判断 |
| 重新处理 | 文件被替换/重下（指纹变化）或目标目录改过 → 正常重链 |
| 清空记录 | 命令 `/realtime_link_clear`，或直接删 `linked.json` |
| 安静日志 | 跳过时只记日志、不发通知 |

### 安装配置

监控目录格式 `源目录:目标目录`，一行一个：
```
/你的盘/MOVIEPILOT/某剧/1原文件:/你的盘/MOVIEPILOT/某剧/2硬链
```

> ⚠️ 与内置的 `LinkMonitor` 不冲突，但两个同时启用会各自处理同一批文件，建议只启用一个。
>
> 📌 **柯南不要再用这个插件**（v2.0.0 起）：[柯南全流程入库](#柯南全流程入库conanrename)
> 已把「硬链 → 换算集号 → 入库」合并成一步，再叠加本节的两段式会让同一批文件被处理两次。

## 柯南全流程入库（ConanRename）

按 [银色子弹数据站](https://www.sbsub.com/data/) 的权威映射，把**拆分版集号**换算成 **TMDB 集号**，
并在**同一个插件里**完成「监听做种目录 → 换算 → 硬链入库并刮削」。

v2.0.0 起取代原先的三段式（`实时硬链接+` → `ConanRename 改名` → `目录实时监控`），
配置只有一处，故障点从 3 个降到 1 个。

### 为什么需要它

拆分版与 TMDB 的集号**偏移不是固定的** —— 每插入一次特辑/拆分集，后续偏移就 +1。实测同一批次内就有三种：

| 拆分版区间 | 偏移 | 集数 |
|---|---|---|
| 1201 – 1245 | −58 | 45 |
| 1246 – 1261 | −59 | 16 |
| 1262 – 1274 | −60 | 12 |

固定偏移（如"减 60"）的脚本会**静默改错** 1–2 集，轻则刮削错集，重则与已有文件撞名覆盖。

更麻烦的是**数据源本身滞后**：sbsub 对当周新集的映射常晚数小时到一天（实测拆分版 1281
到货于 19:37，映射次日 08:40 才出现）。旧版遇到这种情况就把文件丢进 `_待人工` 且永不重试，
后面的入库插件又把它原样搬进媒体库 —— 库里于是出现**错误集号**的文件，订阅还把错号记成「已下载」。

### 集号换算优先级

| 顺序 | 依据 | 说明 |
|---|---|---|
| 1 | 补充映射 | 手工指定，如 `1262=S0E34`（特辑 / 未计入总集数的集） |
| 2 | sbsub 精确映射 | 数据源有该拆分版号 |
| 3 | **tail 偏移外推** | 沿用映射表**最后一段**的偏移，保证「下载时算出的集号」与「入库时算出的集号」一致；超出宽限窗口则不猜 |
| 4 | 隔离 | 解析不出集号 / 超出窗口 → 进隔离目录，不入库，每轮重试并告警 |

**事后自纠**：外推结果记进账本（`source=extrapolated`）。数据源后续补上精确映射且与外推值不同时，
插件自动把库内文件改名到正确集号（连带 nfo/jpg，并且同时替换 `SxxExx` 与「第 N 集」两处），发通知。

### 功能

- 实时监控（`fast` = inotify；SMB/NFS 可用 `compatibility` 轮询），另有可选定时全量扫描兜底
- 入库走宿主 `TransferChain`，默认 **`link`（硬链）**：**源文件（做种）永不移动、不删除**
- 同源文件按 `(size, mtime, ino)` 指纹判重；重下 / 替换会自动重跑
- 目标已存在不覆盖（`overwrite_mode=never`）
- 「仅预演」只打印计划，不调宿主、不写库
- **首次启用 bootstrap**：把做种目录里已有的历史文件一次性登记为 `legacy`（只登记、不入库），
  避免插件上线后把上千个老文件重跑一遍；跑完自动关闭开关
- **页面显示**：上次运行统计、账本最近 50 条（文件 → 拆分版号 → TMDB 号 → 来源 → 阶段）、当前映射区间表
- **识别词同步**：按当前映射的每个偏移区间各生成一条「区间限定」识别词写回订阅；
  可独立 cron、可手动、可预览。只动插件维护的注释区块，订阅里其它识别词不受影响

### 推荐配置

```
做种目录:     /你的盘/MOVIEPILOT/柯南/1柯南做种
媒体库目录:   /你的盘/MOVIEPILOT/LINK/TV
监控模式:     fast
入库方式:     link
TMDB ID:      30983        留空则按标题识别，建议填上避免识别抖动
外推宽限:     30           超出「映射最大拆分版 + 30」不猜，进隔离
隔离目录:     /你的盘/MOVIEPILOT/柯南/_隔离
全量扫描定时: */15 * * * * （留空则只靠实时监控）
补充映射:     1134=S0E32
              1262=S0E34

启用识别词同步: 开
目标订阅:       <在插件里勾选你的柯南订阅>
识别词写法:     每个偏移区间一条
同步定时:       0 8 * * *
前定位词:       Conan[\s.]S01E
后定位词:       [\s.]1996
```

### 从 1.x 升级

1. 首次保存时**勾上「首次启用：把做种目录里已有的历史文件一次性入账」**，跑一次后再关；
2. 停用旧链路：`实时硬链接+` 里移除柯南监控目录、`目录实时监控（分身）` 移除
   `3柯南重命名 → LINK/TV` 条目、旧 `ConanRename` 的 cron 由新版接管；
3. 旧数据目录里的 `rename-*.jsonl` 保留作历史，不会被读取或覆盖。

### 识别词同步写了什么

订阅的「自定义识别词」会变成这样（插件维护的区块，`#` 开头是注释、MP 会跳过）：

```
# >>> ConanRename 自动同步（插件维护，请勿手改）
Conan[\s.]S01E(?=0*(?:12(?:4(?:6|[7-9])|5[0-9]|6(?:0|1)))(?:\D|$)) <> [\s.]1996 >> EP-59
Conan[\s.]S01E(?=0*(?:12(?:6(?:3|[4-9])|7(?:[0-3]|4)))(?:\D|$)) <> [\s.]1996 >> EP-60
# <<< ConanRename 自动同步区块结束
```

每条规则只对**它那一段集号**生效，所以历史缺集搜索也能换算正确。
手动写在订阅里的同形规则会被接管（避免抢命中）。

> ⚠️ **定位词必须同时容忍「点」和「空格」**（所以默认值是 `Conan[\s.]S01E` / `[\s.]1996`）：
> 本地文件名用点分隔（`Detective.Conan.S01E1215.1996...`），但**站点种子名用空格分隔**
> （`Detective Conan S01E1215 1996 ...`）。而订阅搜索匹配的是**种子名**。
> 只认点的话，MP 的前定位词匹配失败会**静默跳过整条偏移规则**，订阅就按字面集号下载。

### 柯南订阅整理流程（v2.0.0）

> 先在媒体库目录**之外**建一个「柯南」文件夹（下文用 `/你的盘/MOVIEPILOT/柯南/` 代表示例路径，
> 换成你自己的媒体盘与目录名）—— **不要放在 MoviePilot 已设置的自动整理目录下**，
> 否则文件会被 MP 的自动整理提前搬走、打断流程。

```
① MP 订阅「名侦探柯南」
   关键词：Detective Conan S01 1996 1080p WEB-DL H264 AAC-ADWeb
   保存路径：/你的盘/MOVIEPILOT/柯南/1柯南做种/
   识别词：由本插件的「识别词同步」自动维护
        ↓ 自动搜索 → 发给 QB 下载
② QB 下载 → /你的盘/MOVIEPILOT/柯南/1柯南做种/    （做种：文件一直留在这）
        ↓【本插件：监听 → 换算集号 → 硬链入库 + 刮削】
③ /你的盘/MOVIEPILOT/LINK/TV/<分类>/名侦探柯南 (1996)/Season 1/
```

| 环节 | 由谁负责 |
|---|---|
| ① 订阅搜索 | MP 订阅 + 本插件的识别词同步 |
| ② 下载 | QB（默认下载器） |
| ③ 换算 + 入库 + 刮削 | **本插件（一个就够）** |

**为什么这么设计**

- **做种与入库解耦**：全程硬链，`1柯南做种` 里的文件永远不动，PT 做种不受影响；清理时删库里的硬链即可。
- **少两次 IO、少两个故障点**：不再产生 `2柯南硬链` / `3柯南重命名` 两个中间目录，也不再需要
  第三个插件接手；改名与入库是同一个决策，不存在"两套规则打架"。
- **不再有死目录**：映射没到不是"丢进 `_待人工` 等死"，而是按最后一段偏移先入库，等映射到了再自纠。

## 呀哈哈封面工坊（YahahaCoverStudio）

第三方插件「呀哈哈封面工坊」（作者 [呀哈哈](https://github.com/justzerock)，上游仓库 [justzerock/MoviePilot-Plugins](https://github.com/justzerock/MoviePilot-Plugins)）的**补丁版**，基于上游 **2.2.10**。

### 打了什么补丁

原本只有「静态方案」（自定义静态布局编辑器）能设**背景色来源**，动态方案只能吃全局配置，而且背景永远是"模糊主图混颜色"（方案 3 还固定带一层左→右变白渐变）。补丁后：

| 位置 | 说明 |
|---|---|
| 封面工坊 → 方案列表 → 动态方案的齿轮 → **动态方案 N 配置** | 新增「**背景类型**」：模糊主图（原行为）/ **纯色** / **纯色渐变**（左深右浅，用所选颜色生成） |
| 同一面板 | 新增「**背景色来源**」：从主图自动取色 / 手动指定 / 配置指定；选「手动指定」时出现「**手动颜色**」拾色器 |
| 纯色模式 | 背景 = 所选颜色**原样铺满**（不压暗、不加噪点、不做渐变），4 个动态风格都支持 |
| 纯色渐变模式 | 背景 = 用所选颜色生成的**左深右浅横向渐变**（插件原生「纯色渐变」同款算法），方案 3 原先只能靠全局开关碰运气，现在每个方案都能单独设 |
| 保存 | 随该方案的动态参数一起保存（`bg_style` / `bg_color_mode` / `custom_bg_color`），**每个动态方案可各不相同** |
| 页面模拟预览 | 自动跟随该设置，所见即所得 |

另外修了一个原生小毛病：**重载/停止插件后，动图预览会被内部遗留的"停止标志"挡住**（日志「检测到停止信号，跳过动图生成」），现在重载后预览直接可用。

静态方案、全局背景色设置的行为**保持不变**；未设置过的动态方案沿用原行为（模糊主图 + 全局背景色）。

### 上游更新后怎么重打

见 [`docs/呀哈哈封面工坊-上游升级后如何重打.md`](docs/呀哈哈封面工坊-上游升级后如何重打.md)，补丁文件在 [`patches/`](patches/)。

## Hosts 自动更新（HostsAutoUpdate）

### 为什么需要它

**明文 DNS 只会在两种结果里二选一：超时，或者返回一个假 IP。**

排查实例（2026-10-01）：MoviePilot 探索页 Bangumi 封面全裂。查下来不是白名单问题、不是代理问题：

| DNS 服务器 | `lain.bgm.tv` 解析结果 |
|---|---|
| 家用路由器（明文） | ❌ SERVFAIL |
| 公共明文 DNS | ⚠️ 返回假 IP |
| **加密 DNS（DoH / DoT）** | ✅ 真实的 Cloudflare IP |

而 **MP 跑在容器里，它的 DNS 走宿主机 → 路由器，压根不经过 Clash** —— 所以改 Clash 配置、加图片代理都无效。

`/etc/hosts` 的作用是**绕过 DNS 直接给 IP**（与 `docker-compose` 的 `extra_hosts` 同理）。
本插件把这件事自动化：**查 → 比对 → 写 → 通知**。

### 功能

- 定期用 **DoH（加密 DNS）** 查询域名清单里每个域名的真实 IP
- 写入**容器内** `/etc/hosts` 的插件专属区块（`# >>> HostsAutoUpdate …` / `# <<<` 标记）
- **IP 变了才写**；无变化不碰文件
- **容器重建后自动重写** —— Docker 会重置 `/etc/hosts`，插件在 MP 启动时会补写
- 查询失败的域名**保留上一次的值**，不会被清空
- 每次写入前**自动备份**到插件数据目录（`hosts.bak.YYYYMMDD-HHMMSS`）
- 支持定时 / 手动执行 / 命令 / 通知

### 多 DoH 交叉验证（本插件的核心设计）

**单个 DoH 服务器返回的结果，本身无法判断对错。**

实测证据：`doh.pub` 对 `api.bgm.tv` **偶尔**返回假 IP（抓到过一次 `179.60.193.16`），
随后连查 10 次又全部正确 —— **污染是间歇性的**，单次查询可能恰好撞上。

所以插件支持填**多个** DoH 服务器，并取各来源 IP 的**交集**：

| 情况 | 处理 |
|------|------|
| 多个来源结果**一致**（交集非空）| ✅ 采用 —— 多个独立来源吻合，基本可排除污染 |
| 结果**不一致**（交集为空）| ⚠️ **跳过该域名并告警** —— 疑似污染，宁可不写也不写错 |
| 只有**一个**来源成功 | 采用，但日志/通知标注「未交叉验证」 |
| 全部失败 | 保留上一次的值，不清空 |

> ⚠️ 比对用的是 **IP 集合**而不是「第一个 IP」—— 不同 DoH 返回的 IP **顺序本来就不同**
> （Cloudflare 和 Google 给的三个 IP 顺序就不一样），只比首个会误判成"不一致"。

### 推荐配置

```
启用插件:      开
域名清单:      lain.bgm.tv
               api.bgm.tv
               bgm.tv
DoH 服务器:    https://doh.pub/dns-query            ← 国内直连可达
               https://cloudflare-dns.com/dns-query  ← 最权威（需走代理）
DoH 走代理:    开
定时更新:      0 */6 * * *       （每 6 小时）
发送通知:      按需
```

**关于代理**：`dns.google` / `cloudflare-dns.com` 在国内**直连不通**，需要勾「DoH 请求走系统代理」
（用的是 MoviePilot 的系统代理设置 `settings.PROXY`）。
`doh.pub` 直连可达，所以上面这个组合即使没配代理也至少有一个来源能用。

### 排查与触发

| 方式 | 说明 |
|---|---|
| 插件页面 | 直接显示当前 `/etc/hosts` 里这些域名的生效记录 |
| `/hosts_update` 命令 | 在 MP 里发命令立即更新一次 |
| `GET /api/v1/plugin/HostsAutoUpdate/hosts_update?apikey=<token>` | 接口触发 |
| `GET /api/v1/plugin/HostsAutoUpdate/hosts_status?apikey=<token>` | 查看当前记录 |

### 注意

- 写的是**容器内**的 hosts，**只影响 MoviePilot 自己**，不动宿主机、不动其它容器
- 域名清单填任意被 DNS 污染的域名即可，不限于 Bangumi
- 容器内 `/etc/hosts` 是 Docker 的 bind mount，**不能原子替换**（会 EBUSY），插件用的是就地覆盖写

## 自动订阅助手（AutomaticSubscriptionAssistant）

基于第三方插件 **自动订阅助手 3.1.0**（作者 [Aqr-K](https://github.com/Aqr-K)，GPL-3.0）的补丁版，本地修订 **3.1.0.4**。

### 为什么需要它

这个插件会自动聚合豆瓣榜单 / 猫眼榜单 / Netflix / 热门媒体 / 蜜柑等来源并**自动订阅** —— 订阅一落地，MoviePilot 就会自动搜索并**下载**。
但很多时候我们只想知道"**有资源了**"，下不下、下哪版想自己决定。

### 改成了什么

| 能力 | 说明 |
|---|---|
| **仅通知模式**（开关，默认开） | 本插件添加的订阅一律以**暂停(S)** 落地 → MP 不搜索、不下载；检测任务每轮还会把漏网的"订阅中"重新按回暂停 |
| **资源检测**（cron 可配，默认每 6 小时） | 对暂停中的订阅逐条**复刻宿主订阅搜索链**（识别 → 缺集 → 订阅规则组/过滤参数 → 标题/年份/季集匹配）检测，只对宿主真正保留的资源发通知——被规则组挡下的不再误报，同名不同片的假阳性（如《八仙》）由宿主匹配管线消除。命中即发通知：标题为「片名 (年份) [Sxx] 检测到有效资源」，正文经**宿主原生「订阅完成」模板渲染**（评分 / 来自用户 / 演员 / 简介）+ 有效资源数 + 仅通知脚注。同一订阅 3 天内只通知一次；每轮最多检测 50 条（超出下轮继续） |
| **仅通知豁免**（订阅管理页 · 卡片菜单） | 点「**豁免仅通知**」→ 该订阅恢复下载，且此后不再被自动暂停（卡片标记「已豁免」）；点「取消豁免」重新纳入仅通知 |
| 恢复自动下载 | 关掉「仅通知模式」开关 → 本插件订阅恢复「订阅中」（也能在订阅管理页逐条恢复/豁免） |
| ⓘ 操作说明 | 配置页「仅通知模式」旁的 ⓘ 图标，悬停可见：豁免规则 + 「只点恢复会在下一轮被再次暂停」的行为说明 |

> **作用范围**：只限**本插件添加的订阅**（按「订阅用户名」过滤，默认 `自动订阅助手`）——你自己手动添加的订阅不会被本插件修改（写操作还有用户名归属二次校验兜底）。

### 安装配置

- 配置页新增「**仅通知模式**」分组：开关 + 资源检测周期（cron，默认 `0 */6 * * *`）
- 订阅管理页每张卡片菜单：**豁免仅通知 / 取消豁免**（原有 恢复 / 暂停 / 退订 语义不变）
- 界面文案三语言（简中 / 繁中 / 英）
