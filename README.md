# 实时硬链接+ （LinkMonitorPlus）

MoviePilot 插件：监控目录文件变化，按原文件名硬链接。
**增强点：记录已处理文件，硬链被转移/入库后不再重复生成。**

> 本插件基于 MoviePilot 内置插件 **LinkMonitor 1.7.1**（作者 [jxxghp](https://github.com/jxxghp)）修改而来。
> 原版逻辑与本插件的关系、以及许可说明见文末。

---

## 一、为什么需要它

原版「实时硬链接」判断"这个文件处理过没有"的方式只有一个：**看目标路径有没有文件**。

于是这个流程会出问题：

```
1原文件/xxx.mkv        ← 源文件（被监控）
   └─硬链→ 2硬链/xxx.mkv
              └─(脚本改名/整理搬走)→ 媒体库/xxx.mkv
```

链接被搬走之后，目标路径就空了 → 下次全量同步（或目录事件）**它又会重新链接一次**，产生多余的硬链、触发多余整理，甚至污染媒体库。

## 二、改成了什么

| 能力 | 说明 |
|---|---|
| **已处理记录** | 记录 `源文件绝对路径 → {size, mtime, ino, target}`，落盘在插件数据目录 `linked.json` |
| **跳过判据（主）** | 记录存在 + 指纹一致 + 目标目录没变 → 跳过（**目标被搬走也算处理过**） |
| **自动补登记** | 链接成功时登记；**目标文件已存在时也会登记** → 升级后跑一次全量同步，现有文件会自动进入记录 |
| **兜底判据** | 记录不存在时，用 `st_nlink > 1` 判断（认得出更早之前已生成的硬链） |
| **重新处理的情形** | 文件被替换/重新下载（大小或修改时间变化）、或监控目标目录被改过 → 正常重新链接 |
| **清空记录** | 命令 `/realtime_link_clear`，或接口 `GET /api/v1/plugin/LinkMonitorPlus/realtime_link_clear?apikey=<MP_API_TOKEN>`；也可以直接删除记录文件 |
| **安静日志** | 跳过时只记日志、不再发送"硬链接完成"通知（全量同步不再刷屏） |

## 三、安装

1. MoviePilot → 设定 → 插件 → **添加插件仓库**：
   ```
   https://github.com/libremk66/MoviePilot-Plugins
   ```
2. 在插件市场里找到 **实时硬链接+**，安装并启用。
3. 配置「监控目录」：一行一个，格式 `源目录:目标目录`（与原版一致）。
   ```
   /你的盘/MOVIEPILOT/1柯南做种:/你的盘/MOVIEPILOT/2柯南硬链
   ```

> ⚠️ 插件 id 为 `LinkMonitorPlus`，**与内置的 `LinkMonitor` 不冲突**，可以共存；但两个同时启用会各自处理同一批文件，建议只启用其中一个。

## 四、记录文件与维护

```
/config/plugins/LinkMonitorPlus/linked.json      # {源文件路径: {size, mtime, ino, target}}
```

- 位置在 `/config` 下，**容器重建、MP 升级都不会丢**（和插件代码不同）。
- 想让某个文件重新处理：删掉 json 里对应那条；想全部重来：删除整个文件，或调用上面的清空接口。
- 记录会随文件增长（每个处理过的文件一条），一般几 KB ~ 几百 KB，无需特别维护。

## 五、已知限制

1. **跨文件系统的情况兜底判据不适用**：如果整理是把文件"复制+删除"到另一块盘，源文件的链接数会掉回 1，此时只能靠**记录**判断（记录仍然有效，因为它记的是"处理过"这件事，与链接数无关）。
2. 如果源文件本来就有其它硬链接（例如别处也链了它做种），在**没有记录**的情况下会被 `st_nlink > 1` 判为"已处理"而跳过；一旦它被记录过一次，之后就完全以记录为准。
3. 插件代码随镜像分发，**MP 升级/容器重建后，如果本插件是从市场安装的则不受影响**；若你把它当作内置补丁直接改镜像里的文件，则升级会覆盖。
