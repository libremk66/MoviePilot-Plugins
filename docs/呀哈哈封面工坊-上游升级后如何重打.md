# 呀哈哈封面工坊：上游更新后如何重打补丁

本仓库的 `YahahaCoverStudio`（`plugins/yahahacoverstudio` 与 `plugins.v3/yahahacoverstudio`，两份内容一致）
= 上游插件 **+ 一个补丁**：*动态方案 1–4 各自支持设置「背景色来源」*。

- 上游仓库：<https://github.com/justzerock/MoviePilot-Plugins>（分支 `main`）
  - 插件主体：`plugins.v2/yahahacoverstudio/`
  - 前端源码（Vue3 + Vuetify + Vite）：`mcg_frontend/`
- 本仓库当前版本：**2.2.10.1**（= 上游 2.2.10 + 补丁）
- 补丁文件：[`patches/yahahacoverstudio-动态方案背景色来源.patch`](../patches/yahahacoverstudio-动态方案背景色来源.patch)
- 本机工作区（含 git 历史：基线提交 + 补丁提交）：`/你的工作区/yahaha-coverstudio/`

---

## 一、上游发新版后：标准重打流程

```bash
# ① 取上游新版源码
git clone --depth 1 https://github.com/justzerock/MoviePilot-Plugins /tmp/yh-upstream
cd /tmp/yh-upstream
grep -m1 -n 'plugin_version' plugins.v2/yahahacoverstudio/__init__.py   # 记下新版号，如 2.2.11

# ② 打补丁（自动应用）
git apply /path/to/patches/yahahacoverstudio-动态方案背景色来源.patch
#   若报错 → 见「二、补丁冲突时的手工重打」

# ③ 重新构建前端（dist 是构建产物，必须重新生成，不能沿用旧 dist）
cd mcg_frontend && npm ci && npm run build      # 产物输出到 ../plugins.v2/yahahacoverstudio/dist
cd ..

# ④ 改版本号：上游版号 + 本地修订位
sed -i 's/^    plugin_version = ".*"$/    plugin_version = "2.2.11.1"/' plugins.v2/yahahacoverstudio/__init__.py

# ⑤ 拷进本仓库（两个目录都要，内容一模一样）
REPO=/path/to/MoviePilot-Plugins
rm -rf $REPO/plugins/yahahacoverstudio $REPO/plugins.v3/yahahacoverstudio
cp -r plugins.v2/yahahacoverstudio $REPO/plugins/
cp -r plugins.v2/yahahacoverstudio $REPO/plugins.v3/
find $REPO/plugins*/yahahacoverstudio -name __pycache__ -type d -exec rm -rf {} +

# ⑥ 更新两个清单里 YahahaCoverStudio 的 version 与 history
#    package.v3.json（v3 索引，主程序 v3 读这个）
#    package.v2.json（v2 索引，条目里保留 "v3": false —— 表示「v3 客户端别用这条」）

# ⑦ 提交推送
cd $REPO && git add -A && git commit -m "呀哈哈封面工坊 2.2.11.1：跟随上游 2.2.11 重打动态方案背景色补丁" && git push
```

**版本号规则**：主程序比较版本号是按 `[.-]` 拆段比大小（`compare_version`），所以 `2.2.11.1 > 2.2.11` 成立；
**不要**写成 `2.2.11-p1`/`-patch1` 这类后缀 —— 非数字段会被判成「小于」。
本地修订位（末位 `.1`）只用来让 MP 认出"这比上游的同版本新"，上游再发版就改成 `上游版号.1`。

## 二、补丁冲突时的手工重打

补丁只动 3 个文件；上游改版后若 `git apply` 失败，按下面的改动点重新改一遍即可（都很小）：

### 后端 `plugins.v2/yahahacoverstudio/__init__.py`

| # | 位置 | 改法 |
|---|---|---|
| 1 | 类属性区（约 223 行，`_animated_settings` 附近） | 加 `_bg_color_mode = 'auto'`、`_custom_bg_color = ''`（**必须**：`init_plugin` 会在 `load_config` 之前调用归一化） |
| 2 | `__get_default_animated_settings()` 的返回字典末尾 | 加 `"bg_color_mode": self._bg_color_mode if ... else "auto"`、`"custom_bg_color": self._custom_bg_color or ""`（默认继承全局） |
| 3 | `__normalize_animated_setting()` 的返回字典末尾 | 加这两个键的归一化（mode 限 auto/custom/config，颜色转字符串） |
| 4 | `__generate_image_from_path()` 里构造 `bg_color_config` 处 | 若 `self._cover_style.startswith("animated")`，用 `animated_runtime_settings` 里的 `bg_color_mode`/`custom_bg_color` 覆盖全局值 |
| 5 | `api_status` 与 `api_set_animated_settings` 的返回体 | 各加 `"bg_color_mode"`、`"custom_bg_color"`（前端立即同步用） |

### 前端 `mcg_frontend/src/components/Page.vue`

| # | 位置 | 改法 |
|---|---|---|
| 1 | `const animatedSettings = reactive({...})` | 加 `bgColorMode: 'auto' as 'auto' \| 'custom' \| 'config'`、`customBgColor: ''`，并在其后加 `const defaultAnimatedBgColor = getThemeColor('--mcr-cover-auto-blend')` |
| 2 | `syncAnimatedSettings()` | 从 `source.bg_color_mode` / `source.custom_bg_color` 读取 |
| 3 | `saveAnimatedSettings()` 的 payload | 提交 `bg_color_mode`、`custom_bg_color`（custom 模式且颜色为空时用 `defaultAnimatedBgColor`） |
| 4 | 模板「动态方案 N 配置」网格（`mcr-animated-settings__grid`）里的「背景混色」之后 | 加 `BlueprintSelect` 背景色来源（`animatedBackgroundColorSourceItems`）+ `v-if="animatedSettings.bgColorMode === 'custom'"` 的 `BlueprintField type="color"` 手动颜色 |
| 5 | 其他 items 常量附近 | 加 `animatedBackgroundColorSourceItems`（auto/custom/config 三项，文案与静态方案一致） |
| 6 | `openAnimatedSettings()` 末尾 + 一个 `watch` | 把 `bgColorMode`/`customBgColor` 同步进 `simulationParams`（页面模拟预览跟随） |

### 前端类型 `mcg_frontend/src/types/plugin.ts`

`AnimatedStyleSettings` 加可选字段 `bg_color_mode?: 'auto' | 'custom' | 'config'` 与 `custom_bg_color?: string`。

> 改完记得 `npm run build` —— **dist 必须重新生成**，否则前端还是旧的。

## 三、（可选）部署到正在跑的 MoviePilot

MP 的插件代码在容器 `/app/app/plugins/yahahacoverstudio`（`/config` 才是挂载卷），另有持久化备份
`/config/plugins_backup/yahahacoverstudio`（容器重建时从这里恢复）——**两处都要覆盖**，只改一处会在重建后丢补丁。

```bash
# 容器内（Portainer 透传 Docker archive API，也可用 docker cp）
PUT /api/endpoints/<env>/docker/containers/<id>/archive?path=/app/app/plugins/yahahacoverstudio   # tar 体
# 覆盖文件：__init__.py、dist/assets/__federation_expose_Page-*.{js,css}

# 让 MP 重载这一个插件（不用重启应用）
curl -X POST -H "X-API-KEY: <MP token>" http://<mp地址>/api/v1/plugin/reload/YahahaCoverStudio
```

## 四、两个已知坑

1. **动图预览会被跳过**：插件被停止/重载后内部停止标志 `_event` 一直保持 set，日志打「检测到停止信号，跳过动图生成」，
   动图**预览**会失败，直到下一次真正的封面生成才会清掉。插件原生行为，与补丁无关。
2. **前端资源是 `no-cache`**：MP 提供插件静态资源时带 `Cache-Control: no-cache, must-revalidate`，
   浏览器普通刷新即可拿到新前端，不需要改 `src/constants/ui.ts` 里的 `UI_REV`。
