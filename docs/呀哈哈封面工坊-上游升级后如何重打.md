# 呀哈哈封面工坊：上游更新后如何重打补丁

本仓库的 `YahahaCoverStudio`（`plugins/yahahacoverstudio` 与 `plugins.v3/yahahacoverstudio`，两份内容一致）
= 上游插件 **+ 本地补丁**（当前 = 上游 **2.2.10** + 补丁 → 本仓库版本 **2.2.10.3**）。

补丁内容（三项）：

| # | 内容 | 说明 |
|---|---|---|
| 1 | 动态方案支持**按方案设置背景色来源** | 从主图自动取色 / 手动指定 / 配置指定，静态方案早已支持，动态方案原先只能吃全局配置 |
| 2 | 动态方案支持**纯色 / 纯色渐变背景**（背景类型） | 模糊主图（原行为）/ 纯色（原色铺满）/ 纯色渐变（用所选颜色做左深右浅横向渐变，插件原生同款算法） |
| 3 | 修复**重载插件后动图预览被跳过** | 插件停止/重载后内部停止标志 `_event` 一直是 set，日志打「检测到停止信号」，动图预览全部失败；现在 `init_plugin` 与 `api_preview` 会清掉遗留标志 |

- 上游仓库：<https://github.com/justzerock/MoviePilot-Plugins>（分支 `main`）
  - 插件主体：`plugins.v2/yahahacoverstudio/`
  - 前端源码（Vue3 + Vuetify + Vite）：`mcg_frontend/`
- 补丁文件：[`patches/yahahacoverstudio-本地补丁-基于2.2.10.patch`](../patches/yahahacoverstudio-本地补丁-基于2.2.10.patch)（累计补丁，含上面三项）
- 本机工作区（git 历史：基线 + 补丁提交）：`/你的工作区/yahaha-coverstudio/`

## 一、上游发新版后：标准重打流程

```bash
# ① 取上游新版源码
git clone --depth 1 https://github.com/justzerock/MoviePilot-Plugins /tmp/yh-upstream
cd /tmp/yh-upstream
grep -m1 -n 'plugin_version' plugins.v2/yahahacoverstudio/__init__.py   # 记下新版号，如 2.2.11

# ② 打补丁（累计补丁；若冲突见「二、手工重打」）
git apply /path/to/patches/yahahacoverstudio-本地补丁-基于2.2.10.patch

# ③ 重新构建前端（dist 是构建产物，必须重新生成）
cd mcg_frontend && npm ci && npm run build
cd ..

# ④ 改版本号：上游版号 + 本地修订位（如上游 2.2.11 → 2.2.11.1）
sed -i 's/^    plugin_version = ".*"$/    plugin_version = "2.2.11.1"/' plugins.v2/yahahacoverstudio/__init__.py

# ⑤ 拷进本仓库（两个目录都要，内容一模一样）
REPO=/path/to/MoviePilot-Plugins
rm -rf $REPO/plugins/yahahacoverstudio $REPO/plugins.v3/yahahacoverstudio
cp -r plugins.v2/yahahacoverstudio $REPO/plugins/
cp -r plugins.v2/yahahacoverstudio $REPO/plugins.v3/
find $REPO/plugins*/yahahacoverstudio -name __pycache__ -type d -exec rm -rf {} +

# ⑥ 更新两个清单里 YahahaCoverStudio 的 version 与 history
#    package.v3.json（v3 索引，主程序 v3 读这个）
#    package.v2.json（v2 索引，条目里保留 "v3": false —— 表示「v3 客户端别用这条」）

# ⑦ 提交推送
cd $REPO && git add -A && git commit -m "呀哈哈封面工坊 2.2.11.1：跟随上游重打补丁" && git push
```

**版本号规则**：主程序比较版本号是按 `[.-]` 拆段比大小（`compare_version`），所以 `2.2.11.1 > 2.2.11` 成立；
**不要**写成 `2.2.11-p1` 这类后缀 —— 非数字段会被判成「小于」。上游再发版就改成「新上游版号.1」。

## 二、补丁冲突时的手工重打

### 补丁 1：背景色来源（`bg_color_mode` / `custom_bg_color`）

后端 `plugins.v2/yahahacoverstudio/__init__.py`：

| 位置 | 改法 |
|---|---|
| 类属性区（`_animated_settings` 附近） | 加 `_bg_color_mode = 'auto'`、`_custom_bg_color = ''`（**必须**：`init_plugin` 在 `load_config` 之前就会调用归一化） |
| `__get_default_animated_settings()` 返回字典末尾 | 加这两个键，默认继承全局 `self._bg_color_mode` / `self._custom_bg_color` |
| `__normalize_animated_setting()` 返回字典末尾 | 加这两个键的归一化（mode 限 auto/custom/config） |
| `__generate_image_from_path()` 里构造 `bg_color_config` 处 | 若 `self._cover_style.startswith("animated")`，用 `animated_runtime_settings` 里的值覆盖全局值 |
| `api_status` / `api_set_animated_settings` 返回体 | 各加这两个键 |

前端 `mcg_frontend/src/components/Page.vue`：`animatedSettings` 加 `bgColorMode`/`customBgColor`；
`syncAnimatedSettings()` 读、`saveAnimatedSettings()` 提交；面板加「背景色来源」下拉 +（手动指定时）颜色选择器；
`animatedBackgroundColorSourceItems` 选项数组；`openAnimatedSettings()` 与 watch 里同步进 `simulationParams`。
类型 `mcg_frontend/src/types/plugin.ts` 的 `AnimatedStyleSettings` 加 `bg_color_mode?` / `custom_bg_color?`。

### 补丁 2：纯色背景（`bg_style`）

后端 `__init__.py`：`__get_default_animated_settings()` 加 `"bg_style": "blur"`；
`__normalize_animated_setting()` 加 `bg_style`（限 blur/solid/gradient）；
4 个 `create_style_animated_N(...)` 调用各加 `bg_style=animated_runtime_settings.get("bg_style", "blur")`；
`api_status` / `api_set_animated_settings` 返回体各加 `bg_style`。

四个风格文件 `style/style_animated_1..4.py`：函数签名加 `bg_style="blur"`；背景合成处加分支 ——
`solid` 时用所选颜色**原样**铺满（`Image.new(..., _safe_rgb(base_color))`），跳过模糊、混色、噪点；
`gradient` 时用所选颜色做左深右浅的横向渐变（`_gradient_bg()`：左 = 色×0.65，右 = 提亮到 ≤230，遮罩 `(x/w)^0.7`，
与插件原生 `create_gradient_background()` 一致；`style_animated_3.py` 直接复用自带的 `create_gradient_background()`）；
各文件加 `_safe_rgb()`（颜色规整成 0-255 整数三元组）与 `_gradient_bg()` 两个小工具。

前端 `Page.vue`：`animatedSettings` 加 `bgStyle`；面板加「背景类型」下拉（模糊主图/纯色/纯色渐变），
非「模糊主图」时用 `v-if="bgStyle === 'blur'"` 隐藏「背景模糊」「背景混色」；`animatedBackgroundStyleItems` 选项数组；
sync/serialize 同步。类型文件加 `bg_style?: 'blur' | 'solid' | 'gradient'`。

### 补丁 3：重载后动图预览被跳过

后端 `__init__.py`：`init_plugin()` 开头加 `self._event.clear()`；
`api_preview()` 开头加「无生成任务时清掉遗留停止标志」的守卫。
（根因：MP 重载/停止插件时会调用插件注册的「停止当前更新任务」服务，把 `_event` 置位，之后动图渲染一律被判为“检测到停止信号”。）

> 改完记得 `npm run build` —— **dist 必须重新生成**，否则前端还是旧的。

## 三、（可选）部署到正在跑的 MoviePilot

MP 的插件代码在容器 `/app/app/plugins/yahahacoverstudio`（`/config` 才是挂载卷），另有持久化备份
`/config/plugins_backup/yahahacoverstudio`（容器重建时从这里恢复）——**两处都要覆盖**，只改一处会在重建后丢补丁。

```bash
# 容器内（Portainer 透传 Docker archive API，也可用 docker cp）
PUT /api/endpoints/<env>/docker/containers/<id>/archive?path=/app/app/plugins/yahahacoverstudio   # tar 体
# 覆盖文件：__init__.py、style/style_animated_1..4.py、dist/assets/__federation_expose_Page-*.{js,css}

# 让 MP 重载这一个插件（不用重启应用）
curl -X POST -H "X-API-KEY: <MP token>" http://<mp地址>/api/v1/plugin/reload/YahahaCoverStudio
```

## 四、怎么用（用户视角）

封面工坊 → 方案列表 → 某个**动态方案**的齿轮 → 「动态方案 N 配置」：

| 项 | 说明 |
|---|---|
| 背景类型 | **模糊主图**（原行为）/ **纯色** / **纯色渐变** |
| 背景色来源 | 从主图自动取色 / 手动指定 / 配置指定（`config` 用标题配置里的颜色） |
| 手动颜色 | 「手动指定」时出现；纯色/纯色渐变模式下它就是背景的基准色 |

纯色模式下背景 = 你填的颜色**原样**（`#3366CC` 出来的就是 `#3366CC`），改完点「保存参数」。
