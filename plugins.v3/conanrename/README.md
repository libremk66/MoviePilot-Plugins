# 柯南全流程入库（ConanRename）

柯南一站式入库插件：**监听做种目录 → 集号换算 → 硬链入库并刮削**。

替代原先「LinkMonitorPlus 硬链 + ConanRename 改名 + CloudLinkMonitor 入库」的三段式流水线，
把三个环节并进一个插件，配置只有一处，故障点从 3 个降到 1 个。

## 解决的问题

原流程下，新集经常无法完成重命名：

1. 数据源 sbsub 对当周新集的映射**会滞后数小时到一天**（实测 1281 到货于 19:37，映射次日 08:40 才出现）；
2. 改名插件查不到映射就立刻把文件丢进 `_待人工`，**且永不重试**；
3. 入库插件又把 `_待人工` 里的原始文件原样搬进媒体库 —— 结果库里出现**错误集号**的文件，
   订阅还把错误集号记为「已下载」。

## 集号换算优先级

| 顺序 | 依据 | 说明 |
|---|---|---|
| 1 | 补充映射 | 手工指定，如 `1262=S0E34`（特辑/未计入总集数的集） |
| 2 | sbsub 精确映射 | 数据源有该拆分版号 |
| 3 | **tail 偏移外推** | 沿用映射表**最后一段**的偏移，保证「下载时算出的集号」与「入库时算出的集号」一致；超出「宽限窗口」则不猜 |
| 4 | 隔离 | 解析不出集号 / 超出窗口 → 进隔离目录，不入库，每轮重试并告警 |

**事后自纠**：外推结果会记进账本（`source=extrapolated`）。数据源后续补上精确映射且与外推值
不同时，插件自动把库内文件改名到正确集号（连带 nfo/jpg，并且同时替换 `SxxExx` 与「第 N 集」
两处集号），发通知。

## 安全约定

- 入库走宿主 `TransferChain`，默认 `link`：**源文件（做种）永不移动、不删除**
- 目标已存在不覆盖（`overwrite_mode=never`）
- 同源文件按 `(size, mtime, ino)` 指纹判重；重下/替换会自动重跑
- 「仅预演」只打印计划，不调宿主、不写库
- 识别词只写进插件自己维护的注释区块，订阅里其它识别词一律不动

## 建议配置

```
做种目录:     /你的盘/MOVIEPILOT/柯南/1柯南做种
媒体库目录:   /你的盘/MOVIEPILOT/LINK/TV
监控模式:     fast（inotify 实时；SMB/NFS 选 compatibility）
入库方式:     link
TMDB ID:      30983        留空则按标题识别，建议填上避免识别抖动
外推宽限:     30           超出「映射最大拆分版 + 30」不猜，进隔离
隔离目录:     /你的盘/MOVIEPILOT/柯南/_隔离
全量扫描定时: */15 * * * * （留空则只靠实时监控）
```

### 2.0.2 修复

映射数据改为**分层兜底**，sbsub 不可用时不再整条链路停摆：

1. **仓库快照兜底**：主源（`cloud.sbsub.com`）拉取失败时，自动改用本仓库的
   `conan-mapping/mapping.json`——jsDelivr 优先、raw.githubusercontent 其次。
   该快照由仓库脚本定时同步 sbsub，内容有变化才提交，diff 天然是逐集增量。
2. **取新不取旧**：快照可能比本地缓存旧（CDN 缓存），选数据时比较映射覆盖上限，
   绝不让 TMDB 集号回退。
3. **失败退避**：主源与快照全部失败时按 30 分钟退避，避免实时监控的每轮防抖
   都去等「主源 30s + 快照 15s×N」的超时，造成线程堆积。
4. **页面显示来源**：映射概览里标注当前数据来自「sbsub 实时 / 缓存 / 仓库快照 / 过期缓存」。

> 快照只含插件真正用到的「拆分版号 → TMDB 号」映射，约 15 KB；两条半集特辑
> （1134 / 1262）仍由 `extra_map` 唯一提供，不进快照。

### 2.0.1 修复


2.0.0 在真实环境验证时暴露出三处运行时缺陷，均已修复：

1. **监控线程停止不彻底**：watchdog 的 `observer.stop()` 后没有 `join()`，插件重载时旧线程仍在跑，
   与新实例重复监听同一目录。
2. **运行时状态跨实例共享**：队列 / observer 列表 / 锁被声明为类属性，重载后新旧实例共用同一份；
   旧实例已停止后仍会接收事件，导致新文件"收到了但不处理"。
3. **防抖回调自锁**：防抖定时器回调先获取运行锁再调用主流程，而主流程内部也获取同一把
   非重入锁 —— 实时监控收到文件后永久卡在第二次 `acquire()`。

> 现在实时链路已在生产环境实测：新集落地 → 60 秒防抖 → 换算集号 → 硬链入库 → 发送通知。

### 从 1.x 升级

1. 配置里多了一项 **「首次启用：把做种目录里已有的历史文件一次性入账」**。
   第一次保存时**勾上**它再跑一次，插件会把目录里已有的文件登记为 `legacy`（只登记、不入库），
   避免把上千个老文件重跑一遍；跑完会自动关闭。
2. 升级后请把旧的三段式停用：`LinkMonitorPlus` 的柯南监控目录、`CloudLinkMonitor2` 的
   `3柯南重命名 → LINK/TV` 监控条目、以及旧的 `ConanRename` cron（新版会接管）。
3. 旧数据目录里的 `rename-*.jsonl` 保留作历史，不会被读取或覆盖。

## 数据文件（插件数据目录）

| 文件 | 用途 |
|---|---|
| `pipeline.json` | 入库账本：源文件指纹、拆分版号、TMDB 集号、来源（exact/extra/extrapolated）、库内路径 |
| `sbsub-data.json` | 映射数据缓存（默认 20 分钟） |
| `mapping-fallback.json` | 仓库快照的本地副本（主源与网络都不可用时兜底） |
